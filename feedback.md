B. The OptimizedFlatList Fixed-Height TrapIn Section 5.2, OptimizedFlatList precomputes scroll offsets using a single fixed itemHeight:   TypeScriptgetItemLayout={(data, index) => ({
  length: itemHeight,
  offset: itemHeight * index,
  index,
})}
Why this breaks in SDUI: A dynamic SDUI page or ENTITY_LIST renders heterogenous rows—a STATUS_BANNER might be 64px tall, a METRIC_CARD 140px, and an expandable Medical Adherence card 220px. Passing a fixed itemHeight to getItemLayout when cell heights vary causes severe visual overlapping and broken scroll jumps.   The Fix: Replace fixed getItemLayout on dynamic lists with a Component-Type Height Dictionary (ITEM_HEIGHT_BY_TOKEN[item.type]) that computes cumulative prefix-sum offsets, or migrate OptimizedVirtualizedList to @shopify/flash-list using getItemType={(item) => item.componentToken} so native cell recycling pools views by SDUI token type.C. When a user toggles a switch in TOGGLE_ROW, adjusts a quota slider, or taps ACTION_BUTTON, how does the JSON schema tell the client what to execute? You need to add a formal Action Discriminated Union (SDUIActionSchema) in @internal/contracts:   API_MUTATION: { type: 'API_MUTATION', endpoint: '/v1/banking/freeze-card', method: 'POST', optimisticPatch: { ... }, rollbackOnFail: true, enqueueOfflineOutbox: true }NAVIGATION: { type: 'NAVIGATE', targetRoute: 'DYNAMIC_SDUI', params: { pageId: 'medical-sos' } }NATIVE_BRIDGE_INVOCATION: { type: 'NATIVE_BRIDGE', capability: 'BIOMETRIC_UNLOCK' | 'QR_SCAN' | 'BLE_PROBE' | 'HAPTIC_HEAVY', onSuccessAction: { ... } }OPEN_MODAL_SHEET: { type: 'OPEN_SHEET', sheetSchema: DynamicSectionDefinition }D. Component-Level Error Boundaries & Skeleton TwinsSection 4 (#34) defines a GlobalErrorBoundary.tsx. However, in an SDUI architecture, if the BFF sends a malformed payload for a single widget (or an older mobile binary encounters a brand-new COMPONENT_TOKEN it doesn't recognize yet), GlobalErrorBoundary will tear down the entire screen.   Wrap Every DynamicComponentRegistry Entry in an <SDUIComponentBoundary>: If one widget fails Zod parsing or throws during render, render a compact inline fallback card (or silently hide it in production while logging a [WARN] telemetry event to the BFF) so the rest of the screen remains usable.   1:1 Skeleton Twins: Every component registered in DynamicComponentRegistry (METRIC_CARD, ENTITY_LIST, etc.) should export a static .Skeleton sub-component (MetricCard.Skeleton) so UniversalDynamicPage can render layout-accurate shimmer placeholders before the BFF payload resolves, eliminating layout shift.
