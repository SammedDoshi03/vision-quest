## 3. BFF (Backend-For-Frontend) Service Contract

The UI code must never import Firebase packages directly. It communicates exclusively through strongly typed contracts.

```typescript
// src/bff/contracts/IReminderService.ts
export type ReminderStatus = 'DUE_NOW' | 'TAKEN' | 'MISSED' | 'UPCOMING';

export interface MedicationSchedule {
  id: string;
  medicineName: string;
  dosage: string;
  scheduledTime: string; // HH:mm
  status: ReminderStatus;
  pillColorHex?: string;
}

export interface IReminderService {
  getTodaySchedules(patientId: string): Promise<MedicationSchedule[]>;
  markAsTaken(patientId: string, reminderId: string): Promise<void>;
  createReminder(patientId: string, reminder: Omit<MedicationSchedule, 'id' | 'status'>): Promise<string>;
  updateReminder(patientId: string, reminder: MedicationSchedule): Promise<void>;
  deleteReminder(patientId: string, reminderId: string): Promise<void>;
}

```

**Offline Outbox Pattern:**

1. When the patient taps **"I Took It"**, the local Zustand store records the action immediately and marks the schedule as `TAKEN` locally.
2. An offline action is appended to the local sync queue (`AsyncStorage` / SQLite).
3. The BFF adapter listens for network re-connection and flushes queued writes to Firebase Realtime Database in the background.

## 4. Offline Alarms & Local Notifications Architecture

Medication reminders for elderly users require exact timing even during Android Doze mode or iOS background restrictions.

1. **Android Setup:**
* Use `SCHEDULE_EXACT_ALARM` and `POST_NOTIFICATIONS` permissions.
* High-priority notification channel (`importance: AndroidImportance.MAX`) with sound enabled and vibration pattern `[0, 500, 200, 500]`.
* Action categories: `"MEDICATION_REMINDER"` with actions:
* `TAKEN` -> triggers `IReminderService.markAsTaken()` directly from the notification response without opening the full UI.
* `SNOOZE` -> reschedules notification in 10 minutes.




2. **iOS Setup:**
* Critical alerts entitlement (if enterprise/approved) or high-priority banner notifications with sound (`sound: 'medication_chime.wav'`).


3. **Rescheduling Engine:**
* On device boot (`BOOT_COMPLETED`), a background task re-reads the local database and re-registers the next 7 days of daily notifications via `expo-notifications`.
